# BatchServe

Пакетный ML-инференс для нескольких клиентов. Сервис принимает CSV, делит его
на пакеты, применяет выбранную версию модели и отдаёт результат в NDJSON.
Крупное задание не занимает очередь целиком: пакеты разных клиентов чередуются.

## Реализовано

- До миллиона строк, пакеты по 1000. Входные пакеты и результаты хранятся в S3;
  PostgreSQL содержит задания, прогресс, владение пакетами и ссылки на результаты.
- У каждого клиента отдельный API-ключ. Чужие задания недоступны для чтения,
  отмены и скачивания.
- Один выполняющийся пакет на клиента. Следующий клиент выбирается по времени
  последнего обслуживания; внутри клиента задания выполняются по времени создания.
- Пакет выдаётся на 30 секунд с уникальным token. Просроченный воркер не может
  зафиксировать результат. Повтор использует новый ключ объекта S3, поэтому
  старый воркер не перезапишет принятый результат.
- Готовые пакеты переживают перезапуск. Ошибка обработки допускает три попытки;
  после исчерпания задание получает статус `failed`.
- Повтор HTTP-загрузки с тем же `Idempotency-Key` и теми же данными возвращает
  прежнее задание. Другие данные или версия модели под прежним ключом дают 409.
- Отмена блокирует поздние результаты. RabbitMQ уведомляет о заданиях,
  периодический опрос PostgreSQL восстанавливает пропущенные уведомления.

Стек: Python 3.11+, FastAPI, PostgreSQL 17, RabbitMQ, MinIO/S3, scikit-learn.
`model.py` содержит реестр моделей, `worker.py` — распределение и защиту результатов,
`api.py` — загрузку, управление и потоковое скачивание.

## Модели и входные данные

`linear-v1` и `linear-v2` — логистические классификаторы двух числовых признаков,
обучаемые на фиксированных синтетических данных с разными seed. Это реальные
модели scikit-learn, но не модели для прикладного использования. Версии и зависимости
зафиксированы в исходниках и `uv.lock`; пользовательские исполняемые модели
и pickle-файлы не принимаются. Версия выбирается при создании задания.

CSV должен иметь заголовок `id,x1,x2`, кодировку UTF-8 и конечные числовые признаки
с модулем не более 1 000 000. Порядок строк сохраняется. Повторяющиеся ID допустимы:
каждая строка является отдельным входным примером.

## Запуск

```sh
docker compose up --build -d
curl -H 'X-API-Key: demo-a-key' http://localhost:8093/health
printf 'id,x1,x2\nexample,1.0,-0.5\n' > /tmp/batchserve-example.csv
curl http://localhost:8093/jobs \
  -H 'X-API-Key: demo-a-key' \
  -H 'Idempotency-Key: 00000000-0000-4000-8000-000000000001' \
  -F 'file=@/tmp/batchserve-example.csv' -F 'model=linear-v1'
```

Подставьте `<id>` из ответа:

```sh
curl -H 'X-API-Key: demo-a-key' http://localhost:8093/jobs/<id>
curl -H 'X-API-Key: demo-a-key' http://localhost:8093/jobs/<id>/result
curl -X POST -H 'X-API-Key: demo-a-key' http://localhost:8093/jobs/<id>/cancel
```

`GET /models` возвращает допустимые версии; `/docs` содержит схему API.
Для второго клиента используется `demo-b-key`. Ключи задаются JSON-объектом
`CLIENT_KEYS`. Порты доступны только на localhost; демонстрационные ключи,
пароли и доступ к S3 нужно заменить перед внешним развёртыванием.

## Проверки

Нужны `uv` и Docker:

```sh
cp .env.example .env
set -a
. ./.env
set +a
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv run python -m scripts.recovery
```

Тесты PostgreSQL используют отдельные временные схемы. Проверяются очередность
клиентов, один активный пакет на клиента, отмена, повторы ошибок, защита от
устаревшего воркера, изоляция клиентов и ключи повторных загрузок.
В тесте HTTP-загрузки хранилище подменяется; полный S3-контур проверяет recovery.

Сценарий recovery создаёт 200 000 строк у одного клиента и одну строку у другого.
Проверяет, что маленькое задание завершается первым, завершает воркер через
SIGKILL, запускает снова и сверяет сохранность готовых пакетов, число и порядок
всех результатов. Возможна пауза до 30 секунд до истечения захваченного пакета.
Не запускайте несколько recovery одновременно: они управляют одним воркером.
CI выполняет тесты и этот сценарий в Docker. Остановка: `docker compose down`.

## Ограничения

Файл ограничен 128 МиБ. Загрузка и деление на пакеты синхронные; список ключей
пакетов хранится в памяти, максимум 1000 ключей. При ошибке загрузки, конкурентном
повторе или отклонённом результате в S3 могут остаться неиспользуемые объекты;
сборщик таких объектов не реализован.

Справедливость обеспечивается по числу пакетов, а не по CPU-времени. Реестр
содержит только быстрые локальные модели. Продления lease нет: пакет должен
успеть за 30 секунд; более медленная модель потребует heartbeat и других лимитов.
Задания одного клиента идут последовательно. Отменённые и неудачные задания
не возобновляются через API; новый запуск требует нового ключа идемпотентности.
Обработка уже начатого пакета при отмене может продолжиться, но её результат
не станет доступен. Квоты хранения и отдельный учёт расходов не реализованы.
